# TERRAIN_MODEL.md — Phase 3 addon to the breakout strategy family

## Purpose and status
Specifies a supply/demand/forced-flow terrain model that gates and modulates the existing breakout/breakdown strategies. This is a **Phase 3 addon** — do NOT implement until: (1) the long-side baseline (BREAKOUT_STRATEGY_PROMPT.md) is accepted, (2) the feature-analysis pass (BREAKOUT_REVERSAL_FEATURES.md) has run, and (3) ideally the short side (BREAKDOWN_SHORT_STRATEGY.md) exists, since half the terrain value is short-side. This doc preserves design intent and defines forward-compatible interfaces so earlier phases don't paint us into a corner.

Read first: BREAKOUT_STRATEGY_PROMPT.md, BREAKOUT_REVERSAL_FEATURES.md, BREAKDOWN_SHORT_STRATEGY.md, DESIGN_DECISIONS.md, VERIFICATION_SCHEME.md.

**REVISION NOTE (post data-source research, Aug 2026):** This doc was revised after an evidence review of on-chain metrics and vendors. Key changes: (a) fusion reduced to three IMMUTABLE sensors — S4 removed from fusion and demoted to a diagnostics/risk-context channel; (b) S3 rebuilt around self-computed, point-in-time-correct data (Coin Metrics Community anchor + self-computed URPD from raw UTXO data) rather than vendor feeds; (c) sensor priors updated — S1 is the lead sensor, S3 is an explicit hypothesis under test with NO independent validation in the literature; (d) MVRV Z-score added as a supervisory GATE-chain candidate (not a terrain sensor); (e) data-immutability rule added; (f) terrain is BTC-first. Evidence basis: the only peer-reviewed on-chain results are cross-sectional (Sakkas & Urquhart 2024 NDF — not applicable to BTC/ETH timing) and a fragile MVRV Z cycle-timing study (Grobys et al. 2026 — 3 round-trips, no costs); the thin-zone/support claim behind S3 has no out-of-sample validation; vendor metric restatement demonstrably inflates naive backtests (Glassnode's own point-in-time study).

## Concept
The data layers below estimate the same latent variable: where resting supply and demand sit relative to current price. Fused, they form a scalar field over price — `terrain(p)` — interpreted as a potential/friction landscape: dense inventory (cost-basis clusters, high-volume nodes) absorbs impulse; vacuum (low-volume nodes) lets impulse traverse fast. Forced-flow (liquidation) structure is tracked separately as risk context, not fused (see S4). The existing strategies detect impulse; the terrain maps the medium. **The strategy logic does not change** — {long, flat, short} state machine, Donchian triggers, hysteresis exits. Terrain plugs in at exactly three injection points: entry gate, exit modulation, size modulation.

## Sensors (each an independent, honest-stubbable brick behind a common interface)

**Common interface:** each sensor returns a normalized density over price buckets for a given timestamp, computed strictly from data available at that timestamp (same look-ahead discipline as everything else). Sensor output is normalized to its own trailing distribution before fusion.

- **S1 — Volume profile (volume-at-price).** Histogram of traded volume over price buckets, rolling lookback window (sweep only {90, 180} days; bucket width in ATR units, not fixed dollars). High-volume nodes = consensus/inventory zones; low-volume nodes = rejection/vacuum zones. Requires intraday bars for sharpness (Kraken/Binance public APIs — this data brick is independently justified by execution modelling and should be built first regardless). Buildable now; highest expected signal per unit effort.
- **S2 — Anchored VWAP set.** Volume-weighted average price from a small, PRE-REGISTERED set of anchors (cycle low, capitulation flushes identified by mechanical rule, major structural events). Each anchor's VWAP = aggregate cost basis of the cohort that bought since. Contributes density mass at each anchored-VWAP level. Anchor set is fixed ex-ante and recorded — anchors may never be added because they "look important" in hindsight.
- **S3 — On-chain cost-basis distribution (crypto-native, highest differentiation, EXPLICIT HYPOTHESIS UNDER TEST).** Cost-basis histogram of the holder base. Build in two immutable layers: (a) **anchor layer** — realized price + MVRV from the Coin Metrics Community API (`CapRealUSD`, `CapMVRVCur`; free, no key, daily, history to 2018+; VERIFY live availability at build time — Community metrics are being trimmed); (b) **distribution layer** — URPD-style histogram SELF-COMPUTED from raw Bitcoin UTXO data (Dune SQL over Bitcoin tables, free tier), validated in shape against free CheckOnChain charts. Self-computation makes the sensor point-in-time-correct by construction and avoids vendor restatement bias. Vendor URPD/STH-LTH feeds (Glassnode Advanced) are a PAID UPGRADE PATH only if the sensor survives step-2 validation — never the primary source. **BTC only initially** (ETH cost-basis tooling is thin/paid); ETH runs on S1+S2 until S3 earns extension. Honest status: the thin-zone/weak-support claim has NO independent out-of-sample validation in the literature — this sensor is the hypothesis the validation ladder exists to test, not established machinery.
- **S4 — Liquidation structure (REMOVED FROM FUSION — diagnostics/risk-context channel only).** Two sub-channels, neither of which gates, sizes, or shapes `terrain(p)`: (a) **DeFi deterministic layer** — exact liquidation levels from public lending-protocol state (DefiLlama liquidations + Aave/Compound/Sky via Dune; free; ground truth, revision-free) — logged per trade for the confluence analysis and usable for short-side stop-placement sanity checks; (b) **CEX heatmaps (Coinglass)** — monitoring-only at most; these are MODELS of positions (assumed leverage brackets), not observations, and fail the epistemic standard applied to S1–S3. Basis for demotion: CEX perps hold ~86% of directional leverage (DeFi maps cover a minority slice), and the one rigorous cascade study (arXiv 2607.27070, preprint) found early-warning signals are event-heterogeneous — no signal preceded all studied cascades. Liquidation structure is context for risk, not a predictive accelerant term.

## Fusion
`terrain(p) = w1·S1(p) + w2·S2(p) + w3·S3(p)` — three immutable sensors; no signed/directional terms (S4 is out of fusion).
- Weights start EQUAL among available (non-stubbed) sensors and STAY equal unless the sensor-level validation (below) shows a sensor failing its null — failed sensors are dropped (weight 0), not down-weighted. Weight tuning is prohibited in this phase. **S1-only terrain is a legitimate reduced scope** if S2/S3 fail or resourcing tightens — simplicity wins ties.
- Derived per-trigger quantities (the only outputs strategies consume):
  - **path_resistance:** integrated terrain mass between entry price and entry + 1×(N_entry-channel width) in the trade direction.
  - **wall_distance:** ATR-distance to the nearest terrain cluster above a density threshold, in the trade direction.
  - **cleared_mass:** terrain mass between the entry price and the channel boundary just cleared (evidence that supply was actually absorbed — the mechanized version of the original breakout rationale).

## Injection points (the ONLY places terrain touches strategy logic)
1. **Entry gate:** accept triggers only when path_resistance is below a quantile threshold of the trailing trigger population (sweep only {median, lower tertile}). Short side additionally vetoes triggers into heavy S3 demand mass below (falling-knife configuration). [S4 "cascade fuel" favoring removed — liquidation data is context, not gate input.]
   - **Separate gate-chain candidate (not terrain): MVRV Z-score supervisory gate.** The single best-evidenced on-chain timing input (Grobys et al. 2026: Sharpe 1.28 vs 0.45 B&H — but 3 round-trips, no transaction costs, single path; treat with a skeptical prior). Enters as one toggleable link in the composable gate chain beside the 200-day SMA gate, one threshold parameter, tested as a standard increment with its own TrialRegistry accounting. Free data (Coin Metrics `CapMVRVCur`). It is a slow cycle-scale scalar, NOT a price-level density — it belongs to the supervisory layer, not `terrain(p)`.
2. **Exit modulation:** trailing exit remains the safety net. When price enters the next dense cluster in the trade direction (wall reached), narrow the hysteresis: switch exit lookback from N_exit to a fast variant (e.g. 10 → 3). Rationale: "exit on confirmed reversal" becomes "exit on first weakness where weakness is expected." Toggleable brick.
3. **Size modulation:** conviction multiplier on the vol-target size, bounded [0.5×, 1.5×], monotone in low path_resistance. Hard position caps from earlier phases still bind. Toggleable brick.

## Data-immutability rule (cross-cutting, added post-research)
Every sensor input must be either (a) self-computed from immutable raw data (exchange OHLCV, raw UTXO set, public contract state) or (b) a vendor metric that is point-in-time/immutable by construction. Mutable, entity-tagged vendor metrics (exchange balances/netflows, whale/entity metrics, tagged miner flows) are PROHIBITED as sensor inputs — vendor restatement demonstrably inflates naive backtests. If a mutable metric is ever considered for diagnostics, it must be lagged and results haircut, and this must be flagged in TERRAIN_RESULTS.md.

## Validation ladder (strict order, no skipping)
1. **Sensor-level null — random levels.** Per sensor, before any fusion: compare reaction statistics at sensor-identified levels vs N pseudo-levels placed randomly (matched to the real map's level density). Statistics: P(reversal within k×ATR of level touch), realized-vol deceleration near level, traversal speed through level. A sensor that fails to beat random placement is dropped from fusion. **Updated priors (post-research):** S1 is the lead sensor (own computation on immutable data; the only family adjacent to validated microstructure work) and is expected to pass; S3 is a genuine open hypothesis — the literature contains zero independent validation of the thin-zone claim, so WP2/WP5 are load-bearing, not confirmatory; S2 marginal, expected to fail, cheap to test. The most likely positive outcome for the programme is exit-modulation/risk value rather than entry-gate alpha — "where a move stalls" is a weaker but more robust claim than "which triggers to take."
2. **Features before gates.** Log path_resistance, wall_distance, cleared_mass per trigger (register as F7, F8, F9 continuing the BREAKOUT_REVERSAL_FEATURES.md numbering) on the EXISTING accepted baselines' trade populations. Quintile analysis of trade outcomes vs each feature is the go/no-go for the whole model — obtained without building any gate. Promotion criteria identical to the features doc: monotonic, walk-forward stable, plateau over thresholds.
3. **Incremental promotion.** Only features passing step 2 become live injection points, added ONE at a time on top of the accepted baseline, each a toggleable brick with its own TrialRegistry entries and multiplicity accounting. Report each increment's marginal contribution.
4. **No joint tuning.** Terrain parameters (lookbacks, quantile thresholds, bucket widths) are swept only within the small stated sets; fusion weights are never tuned. If the equal-weight fusion underperforms the best single sensor in step 2, use the single sensor — simplicity wins ties.

## Diagnostics
- Per-trigger: F7/F8/F9 values, sensor availability mask (which sensors were live vs stubbed at that timestamp)
- Per-sensor: null-test statistics tables, level-density over time
- Gate counterfactuals: triggers rejected by the terrain gate and their hypothetical outcomes (log-only), so the gate's cost in missed winners is measured, not assumed
- Exit-modulation attribution: P&L difference between terrain-modulated exits and the un-modulated safety-net exit on the same trades

## Data plumbing (build order)
1. Intraday OHLCV brick (Kraken/Binance public APIs) — prerequisite for S1, independently justified by execution modelling. Build first.
2. S1 volume profile on that data.
3. S3 anchor layer: Coin Metrics Community API (`CapRealUSD`, `CapMVRVCur`) — verify live free availability first. S3 distribution layer: self-computed URPD from Dune Bitcoin UTXO tables (free tier, 40 req/min), shape-validated against CheckOnChain charts. Vendor URPD = paid upgrade stub only.
4. S2 anchored VWAPs (cheap once intraday data exists; anchor set pre-registered in this doc's repo copy before first test).
5. S4 diagnostics channel (not fusion): DeFi deterministic layer via DefiLlama + protocol state on Dune; CEX heatmaps monitoring-only or omitted. Unscheduled; never blocks anything.
6. F5 note (adjacent, for BREAKOUT_REVERSAL_FEATURES.md): funding/OI from exchange-native APIs — Binance `/fapi/v1/fundingRate` (+ coin-margined variant), Bybit `/v5/market/funding/history` and `/v5/market/open-interest`; free, authoritative, history to ~2019–2020. Prefer native APIs per venue; Coinglass only for cross-venue aggregation.

## Forward-compatibility requirements for earlier phases (apply from Phase 1–2 sessions onward)
1. Per-trade diagnostics schema must accept additional named features without migration (F-numbering is open-ended).
2. The data layer must support multiple bar frequencies per instrument (already required by the timeframe discussion) and additional non-OHLCV sources behind honest stubs.
3. Trigger acceptance must pass through a composable gate chain (the higher-timeframe gate is the first link; terrain gate will be another link, not a rewrite).
4. Exit logic must support runtime switching of exit lookback (needed for exit modulation) — parameterize, don't hardcode.

## Out of scope
Standalone "zone trading" strategies; discretionary zone drawing of any kind; fusion-weight optimization; sensors beyond S1–S3 (+S4 diagnostics channel); mutable entity-tagged metrics as sensor inputs (see immutability rule); equities application (crypto only — S3/S4 don't exist elsewhere); ETH cost-basis work before S3 earns it on BTC; any use of terrain outputs before their sensor passes the random-level null.
